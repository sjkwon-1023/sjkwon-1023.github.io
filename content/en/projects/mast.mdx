On macOS, I worked with several coding agents side by side in cmux. I wanted the same workflow on
my Windows desktop but could not find a suitable tool, so I built a terminal for coding agents
around the features I actually use.

After using it daily on Windows, I started to find cmux on my MacBook lacking. It had none of the
features I had built around my workflow—phone remote control, agent-to-agent handoff, and viewer
tabs—and its heavy RAM use made it feel sluggish once several agents were running. So I added a
native macOS build, and I now use mast every day on both my Windows desktop
at home and my work MacBook. It is currently released as v1.0.0.

## Key features

- **Split panes with per-pane tabs** — Within a workspace, panes split horizontally or vertically,
  and each pane holds multiple tabs. New panes and tabs open in the shell's current working
  directory.
- **Agent status and notifications** — The sidebar shows, for each workspace, whether its agents
  are running, waiting for input, or finished, together with their latest message. A tab that
  starts waiting gets its own badge and a Windows notification.
- **Viewer tabs** — A file explorer, text and Markdown viewers with Markdown editing, a Git changes
  viewer that shows diffs split into working and staged scopes, and a built-in browser tab for
  checking the web page under development.
- **Agent-to-agent collaboration** — Inside a terminal, an agent uses `mast ls` to find the tabs in
  the same workspace and `mast send` to hand work to another pane. With `mast browser`, it
  inspects elements and screenshots in the browser tab, and clicks and types there.
- **Phone remote control** — A phone paired by QR code reads terminal output, scrolls a
  full-screen TUI, and sends input to an agent or a Bash shell.
- **Session restoration** — After a restart, the workspace, split, and tab structure and each tab's
  working directory are restored. In a tab that was running an agent, `Up` recalls the Claude Code
  or Codex resume command.
- **Windows and macOS** — Windows 11 (x64 and ARM64) with WSL2 is the primary environment, and the
  same codebase provides a native Apple Silicon macOS build.

## Tracking agent status per tab

Hooks for Claude Code, Codex, OpenCode, and Antigravity CLI emit OSC 777 tokens—`mast:running`,
`mast:needsInput`, and `mast:idle`—into terminal output. The Rust OSC scanner separates them from
ordinary output and applies the status to the corresponding tab. Standard notifications such as
OSC 9 update only the unread state and message, so other programs do not overwrite coding-agent
status. The existing PTY stream serves as the status channel, with no daemon, IPC server, or named
pipe.

Status is stored per tab, and the sidebar shows the most urgent tab in each workspace. Even with
several agents in one workspace, one tab finishing never overwrites another tab that is still
running, and the tab waiting for input is identifiable at a glance. Status comes only from each
agent's hook signals rather than from screen contents or process names, and the app installs the
hooks inside WSL on first launch.

The UI receives only the running, waiting-for-input, and finished states; raw terminal output is
not converted to JSON. The output hot path remains a byte stream, and only low-frequency events
such as state changes are sent to the UI layer.

## Opening the phone connection safely within the LAN

The phone connects in one of two modes. Local HTTP is enabled in settings and is intended for a
trusted internal network. Secure Remote has a GitHub Pages HTTPS page connect directly to the PC
over WebTransport. The PC issues a self-signed certificate for each pairing, and the phone pins the
certificate's SHA-256 fingerprint carried in the QR code, accepting that certificate alone. The
listener is open only while the QR code is shown, one phone connects at a time, and the certificate
is valid for at most 14 days.

Both modes connect directly to the PC's LAN address without a cloud relay. The pairing dialog
checks the Windows Firewall rules and, when needed, adds the rule after a UAC prompt. The phone
renders the screen with a headless xterm, showing the same content as the desktop.

## Choosing WSL2 as the reference environment

On Windows, a terminal always launches as `ConPTY → wsl.exe → login shell`. I scoped the product to
my working environment, where coding agents and development tools run inside WSL2, and focused on
the core features: splits, tabs, workspace switching, and agent status.

At startup, the app diagnoses WSL once and distinguishes causes such as whether WSL is installed,
whether a distribution exists, and whether the shell starts. When WSL is not ready, it shows the
install command, the official guide, and a Recheck button, while tabs on healthy distributions run
unaffected.

Global shortcuts use `Ctrl+Shift` and `Alt+Shift` combinations so the shell receives its standard
`Ctrl` inputs. `Ctrl+C` copies only when text is selected and otherwise passes SIGINT, preserving
terminal conventions.

## Separating the UI from the terminal lifetime

A UI-framework-independent Rust core owns terminal sessions, flow control, OSC parsing, the replay
buffer, and layout state. Tauri v2 is a thin bridge between the host and the WebView, while vanilla
TypeScript and xterm.js render the interface.

Because of this boundary, a WebView reload used to reclaim memory leaves the PTY session in Rust,
and the new UI reattaches to the current state and scrollback. When the app reopens, it launches
fresh shells in the saved layout and working directories, and each agent continues its earlier
conversation through its own resume command.

The same structure made macOS support possible. Sharing the workspace, pane, and tab model and the
terminal, replay, OSC, and agent-status pipelines, and separating only the platform-specific parts,
I built a native Apple Silicon macOS build that launches zsh or bash directly.

## Adding features within a memory budget

I set a memory target of 100 MB and an upper bound of 150 MB; on an x64 Windows 11 desktop, I
measured the whole process tree including WebView2 at about 129 MB. As features grew, I designed them so
that unused features cost nothing.

- Viewer code and the Markdown parser load when first opened.
- Large files are read in 512 KiB windows, keeping viewer memory use constant.
- A browser tab creates its WebView when first shown, and turning the feature off in settings
  creates none of its resources.
- With every automatic UI reset turned off, the watchdog thread is not created.

## Testing and distribution

The project includes unit and integration tests for the Rust core and UI tests for TypeScript. CI
runs `check` and Clippy for the x64 and ARM64 Windows targets, frontend builds and tests, and an
audit of the public Secure Remote bundle. A soak test that creates and destroys a ConPTY session
500 times confirmed that handle and thread counts stay constant. The macOS build is verified with
PTY lifetime tests against real shells and tests for the CLI and settings merging.

On a release tag, Windows runners build x64 and ARM64 portable executables and attach them to
[GitHub Releases](https://github.com/sjkwon-1023/mast/releases). The app checks for a new release at
launch and shows it in the sidebar.
