처음 해결하려던 문제는 비용보다 평가의 일관성이었습니다. 생성형 LLM을 Judge로 사용하면 같은
기준을 요청해도 응답 형식과 판정이 흔들릴 수 있어, 대규모 배치에서 반복 가능한 자동 평가 방식이
필요했습니다.

비용도 함께 봐야 했습니다. 영어 문항 배치 생성에 들어간 LLM 비용은 누적 수천만원대였고, 생성
뒤의 검증도 고성능 모델을 호출해 문항 하나에 약 50원과 30초가 들었습니다. 다만 이 PoC가 줄이려던
대상은 누적 생성비용 전체가 아니라 문항별 검증비용이었습니다.

## 로컬 SLM 대신 저비용 상용 모델

당시에는 로컬 GPU 자원을 안정적으로 쓰기 어려워 SLM을 직접 서빙하는 방안은 제외했습니다. 대신
기존 파이프라인에서 바로 비교할 수 있는 저비용 상용 API 모델을 후보로 두었습니다. 아래 비용은
실제 운영 청구액이 아니라, 같은 표본의 입출력 토큰 사용량과 당시 API 단가로 계산한 추정치입니다.

## 모델 교체보다 판별 방식부터

저비용 모델에 같은 자유형 평가를 시키는 것만으로는 비용과 판정 안정성을 함께 비교하기
어려웠습니다. 그래서 검증 모델이 설명문을 생성하게 하는 대신, 후보 라벨의 Log Probability를
비교해 판정하는 로직을 만들었습니다. 작업에 필요한 것은 긴 답변이 아니라 기준 통과 여부였기
때문입니다.

저비용 상용 모델의 판정을 기존 고성능 모델의 결과와 대조하고 비용, 처리시간, 정합성과 반복 실행
시의 재현성을 함께 봤습니다. 실험 조건을 맞추기 위해 Prefect 기반 생성·검증·적재 파이프라인에서
반복 실행했습니다.

## PoC에서 나온 숫자

| | 기존 Judge | PoC 후보 |
| --- | --- | --- |
| 문항당 추정 토큰 비용 | 약 50원 | 약 5원 (−90%) |
| 문항당 처리시간 | 약 30초 | 약 15초 (−50%) |

해당 PoC 표본에서는 기존 고성능 모델의 판정과 모두 일치했습니다. 사람의 정답 라벨을 기준으로
측정한 정확도라는 뜻은 아닙니다. 이 범위에서는 검증 단계를 더 저렴한 모델과 짧은 판별 작업으로
분리할 여지가 있다는 가능성을 확인했습니다.

## PoC가 말해 주지 않은 것

해당 표본에서 판정이 모두 일치했지만, 이 결과만으로 다른 문항 유형이나 더 큰 배치에서도 같은
품질이 유지된다고 말할 수는 없습니다. 프로젝트 일정상 유형별 표본 확대와 운영 조건 검증까지
이어가지 못해 실제 파이프라인에는 적용하지 않았습니다. 따라서 이 결과는 비용 절감 성과가 아니라,
저비용 상용 모델을 적용할 가능성과 다음 검증 범위를 좁힌 PoC입니다.
